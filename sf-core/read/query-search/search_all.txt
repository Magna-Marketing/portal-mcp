Tool: search_all

Description
Free-text search across multiple sObjects using SOSL. Use when the user
gives a name or fragment and you don't know which object holds it (e.g.
"find anything mentioning ACME"), or to search big text/long-text fields
which SOQL cannot index. SOSL searches the search index, not raw fields,
so it is eventually consistent (a few seconds behind writes).

Use `query_records` instead when you already know the object and want
deterministic SOQL semantics. Use `search_objects` to discover sObjects
by metadata (not data).

Salesforce API
REST API (Data), v66.0.

Endpoint
GET /services/data/v66.0/search/

Headers
Authorization: Bearer <access_token>
Accept: application/json

Body
None.

Input (parameters)
term (string, required) - The SOSL FIND term; string with at least 2 non-space
characters; no default; example: "Acme" or "\\"Sahitya Sharma\\""; do not include the
FIND keyword, braces, RETURNING clause, or unescaped user-supplied operators.
in (string, optional) - The SOSL search field group; enum string; default "ALL FIELDS";
example: "NAME FIELDS"; do not pass values outside Salesforce SOSL search groups.
returning (object[], optional) - The RETURNING object specifications; non-empty array;
no default; example: [{"sObject":"Account","fields":["Id","Name"],"limit":10}]; do not
pass an empty array or objects without sObject.
  sObject (string, required) - The sObject API name in the RETURNING clause; string such
  as "Account"; no default; example: "Contact"; do not pass labels, relationship paths,
  or multiple objects.
  fields (string[], optional) - The fields to return for this sObject; array of field
  API-name strings; defaults to ["Id"]; example: ["Id", "Name", "Email"]; do not pass
  aggregate expressions, aliases, or relationship subqueries.
  where (string, optional) - The per-object SOSL WHERE condition without the WHERE
  keyword; string; no default; example: "IsActive__c = true"; do not pass SELECT, FROM,
  RETURNING, ORDER BY, LIMIT, or untrusted raw input.
  orderBy (string, optional) - The per-object SOSL ORDER BY clause without the ORDER BY
  keyword; string; no default; example: "Name ASC"; do not pass WHERE, LIMIT, SELECT,
  FROM, or RETURNING.
  limit (integer, optional) - The per-object SOSL row limit; integer from 1 to 200; no
  default; example: 10; do not pass 0, decimals, negatives, or offsets.
limit (integer, optional) - The global SOSL LIMIT across returned records; integer from
1 to 2000; no default; example: 100; do not pass 0, decimals, negatives,.
includeDeleted (boolean, optional) - Whether to add WITH DELETED so deleted records can
be searched where Salesforce supports it; boolean; default false; example: true; do not
pass true unless deleted records are needed.

Result
raw Salesforce SOSL search response, typically an array of records with attributes and
requested fields.

Required permissions
- API Enabled.
- Object read on each RETURNING sObject; FLS on each field.

Idempotency & limits
- Read-only; safe to retry.
- Search index is asynchronously updated; recently saved records may not
  appear for several seconds.
- 2,000 records per query, 200 per RETURNING object.
- Term must be ≥2 alphanumeric chars (single-char terms rejected).

Errors
- MALFORMED_SEARCH: SOSL syntax error or unsupported clause.
- INVALID_FIELD / INVALID_TYPE: field or sObject not visible.
- SEARCH_TOO_BROAD: term matches more than the engine returns.

Example request

search_all({
  "term": "Acme\" or \"\\\\\"Sahitya Sharma\\\\\""
})

Example result

raw Salesforce SOSL search response, typically an array of records with attributes and requested fields.
