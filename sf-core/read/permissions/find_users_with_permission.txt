Tool: find_users_with_permission

Description
Find every active user that has a given permission, anywhere in their
sourcing chain (profile or any permission set / permission set group).
Two flavors:
1. System permission: `permission` is one of the boolean Permissions*
   flags (e.g. "ModifyAllData", "ManageUsers", "ApiEnabled").
2. Object permission: pass `sObject` plus `accessType`
   ("read" | "create" | "edit" | "delete" | "viewall" | "modifyall").

Use this for security audits like "who can ModifyAllData?" or "who can
delete Opportunities?".

Salesforce API
REST API (Data), v66.0.

Endpoint
GET /services/data/v66.0/query/

Headers
Authorization: Bearer <access_token>
Accept: application/json

Body
None.

Input (parameters)
category ("system" | "object" | "field" | "apex" | "vf", required) -
Permission source category to search; enum string; required with no default; example:
object; do not pass labels, plural values, or arbitrary setup entity types.
systemPermissionField (string, optional) -
PermissionSet boolean field for category system; API field name with or without the
Permissions prefix; required only for system; example: PermissionsModifyAllData; do not
pass labels like Modify All Data, multiple fields, or SOQL fragments.
sObjectType (string, optional) -
Object API name for category object or field; Salesforce SObjectType string; required
for object and optional when field is fully qualified; example: Account; do not pass
labels, relationship names, or comma-separated objects.
objectAccess ("read" | "create" | "edit" | "delete" | "viewAllRecords" | "modifyAllRecords" | "viewAllFields", optional) -
Object permission flag for category object; enum string mapped to ObjectPermissions
fields; default read; example: viewAllRecords; do not pass CRUD abbreviations, labels,
or multiple access types.
field (string, optional) -
Fully qualified field API name for category field; string in Object.Field format;
required for field; example: Account.AnnualRevenue; do not pass unqualified names,
labels, wildcards, or comma-separated fields.
setupEntityId (string, optional) -
Setup entity Id for category apex or vf; Salesforce Id of ApexClass or ApexPage;
required for apex and vf; example: 01p5g00000ABCDe; do not pass names or Tooling API
URLs.
includeInactiveUsers (boolean, optional) -
Whether inactive assigned users are included; boolean; default false; example: true; do
not pass when only active users should be returned.
includeExpiredAssignments (boolean, optional) -
Whether expired assignments are included; boolean; default false filters ExpirationDate
before today; example: true; do not pass to focus on active assignments.
limit (integer, optional) -
Maximum assignment rows per assignment query; integer from 1 to 2000; default 200;
example: 100; do not pass 0, negatives, decimals, or offsets.

Result
Returns raw Salesforce QueryResult objects for matching permission sets, components, and
assignments.
totalSize (number) - QueryResult totalSize.
done (boolean) - true when this response contains the full result.
records (array) - sObject rows from the query. Returned unchanged; not renamed.
nextRecordsUrl (string, optional) - present when done is false.
matchingPermissionSets (value) - included in the JSON returned by the tool.
directAssignments (value) - included in the JSON returned by the tool.
groupComponents (value) - included in the JSON returned by the tool.
groupAssignments (value) - included in the JSON returned by the tool.

Required permissions
- "View Setup and Configuration".

Idempotency & limits
- Read-only; safe to retry.
- A truly broad query (e.g. ApiEnabled) can hit many users; the tool
  paginates.

Errors
- INVALID_FIELD: unknown permission name.
- INVALID_TYPE: unknown sObject.

Example request

find_users_with_permission({
  "category": "object"
})

Example result

{
  "totalSize": 1,
  "done": true,
  "records": [
    {
      "attributes": {
        "type": "PermissionSet"
      }
    }
  ]
}
