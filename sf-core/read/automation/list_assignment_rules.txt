Tool: list_assignment_rules

Description
List Lead and Case assignment rules: rule entries (criteria, target user/queue, email template, notify checkbox), and active rule per object. There can be many rules per object but only one is active at a time per Salesforce constraint.

Salesforce API
Metadata API (SOAP), v66.0.

Endpoint
POST /services/Soap/m/66.0   (readMetadata AssignmentRules)

Headers
Authorization: Bearer <access_token>
Accept: application/json

Body
None.

Input (parameters)
sObjects (("Lead" | "Case")[], optional) - AssignmentRules container object API names;
array limited by Salesforce to Lead and Case; default [\"Lead\", \"Case\"]; example:
[\"Case\"]; do not pass custom objects, labels, or SOQL fragments.
namePattern (string, optional) - Rule fullName selection hint using * and ? wildcards;
string; no default; example: Support_*; Metadata API reads whole object containers, so
this does not trim returned container data; do not pass regex or SOQL LIKE syntax.
limit (integer, optional) - Maximum object containers to read; positive integer clamped
by the two valid containers; default reads all selected containers; example: 1; do not
pass 0, negatives, decimals, or offsets.

Result
Returns a JSON object with metadataFullNames and metadataResult.
metadataFullNames (value) - included in the JSON returned by the tool.
metadataResult (value) - included in the JSON returned by the tool.

Required permissions
- "View Setup and Configuration" / "Customize Application".

Idempotency & limits
- Read-only.

Errors
- INVALID_TYPE on bad sObject (only Lead and Case support assignment rules).

Example request

list_assignment_rules({
  "sObjects": "[\\\"Case\\\"]",
  "namePattern": "Support_*",
  "limit": 1
})
