Tool: dml_records

Description
Perform DML (insert / update / delete / upsert) on Salesforce records using
the REST API v66.0. Intelligently routes requests to the most appropriate
endpoint based on record count:

- 1 record      → single sObject endpoint for precise single-record response.
- 2–200 records → sObject Collections endpoint, chunked at batchSize (≤200
                  per request, multiple chunks if needed).
- useBulk=true OR records > 10,000 → Bulk API 2.0: creates job, uploads CSV,
  polls to completion, returns job metadata + result URLs.

Salesforce APIs Used (v66.0)
REST Data API + sObject Collections + Bulk API 2.0.

Single-record endpoints:
- POST   /services/data/v66.0/sobjects/{sObject}                             (insert)
- PATCH  /services/data/v66.0/sobjects/{sObject}/{recordId}                  (update)
- DELETE /services/data/v66.0/sobjects/{sObject}/{recordId}                  (delete)
- PATCH  /services/data/v66.0/sobjects/{sObject}/{externalIdField}/{value}   (upsert)

Collection endpoints (≤200 records per chunk):
- POST   /services/data/v66.0/composite/sobjects                             (collection insert)
- PATCH  /services/data/v66.0/composite/sobjects                             (collection update)
- DELETE /services/data/v66.0/composite/sobjects?ids=...&allOrNone=false     (collection delete)
- PATCH  /services/data/v66.0/composite/sobjects/{sObject}/{externalIdField} (collection upsert)

Bulk API 2.0 (>10,000 records or useBulk=true):
1. POST  /services/data/v66.0/jobs/ingest                  (create job)
2. PUT   {contentUrl from job response}                    (upload CSV data)
3. PATCH /services/data/v66.0/jobs/ingest/{jobId}          (state=UploadComplete)
4. GET   /services/data/v66.0/jobs/ingest/{jobId}          (poll until terminal)
5. GET   /services/data/v66.0/jobs/ingest/{jobId}/successfulResults/
6. GET   /services/data/v66.0/jobs/ingest/{jobId}/failedResults/

Corrections vs original documentation:
- The original doc mentioned "disableValidationRules" as a REST header parameter.
  This is NOT a real Salesforce REST API parameter and has been removed.
  Validation rule bypassing is only possible via Apex with allOrNone or a
  custom permission, not via a REST header.
- "Sforce-Auto-Assign: false" header IS real and is surfaced via
  disableAssignmentRules parameter.
- Collection upsert uses PATCH /composite/sobjects/{sObject}/{externalIdField}
  (all records must be the same sObject type for upsert).
- Bulk API 2.0 only supports CSV (not JSON) as contentType.
- Single-record delete for collections uses query param: ?ids=id1,id2&allOrNone=false

Headers
Authorization: Bearer <access_token>
Content-Type: application/json          (REST and Collections calls)
Content-Type: text/csv                  (Bulk data upload)
Sforce-Auto-Assign: false               (optional; disableAssignmentRules=true)

Input (parameters)
operation (string, required) - "insert" | "update" | "delete" | "upsert".
sObject (string, required) - Salesforce object API name (e.g. "Account").
records (object[], required) - Records to process.
  - insert: plain field objects, no Id field.
  - update: each must include "Id".
  - delete: each must include "Id" (or plain id strings).
  - upsert: each must include the externalIdField value.
externalIdField (string, required when operation="upsert") - External ID field name.
allOrNone (boolean, optional, default false) - Roll back on any failure.
useBulk (boolean, optional) - Force Bulk API 2.0. Auto when records > 10,000.
batchSize (number, optional, default 200) - Collections chunk size; ≤200.
disableAssignmentRules (boolean, optional, default false) - Suppress Lead/Case
  assignment rules via Sforce-Auto-Assign: false header.

Result (single record)
{ results: [{ id, success, errors[], created? }] }
- insert: created=true always.
- update/delete: no 'created' field.
- upsert single: created=true if new record, false if existing.

Result (collections)
{ chunks: [ [SaveResult | DeleteResult, ...], ... ] }
- One sub-array per chunk. Each entry: { id, success, errors[], created? }.
- Errors array is empty on success.

Result (bulk)
{
  job: {
    id, state, object, operation, contentType, apiVersion,
    numberRecordsProcessed, numberRecordsFailed, ...
  },
  successfulResults: "/services/data/v66.0/jobs/ingest/{jobId}/successfulResults/",
  failedResults:     "/services/data/v66.0/jobs/ingest/{jobId}/failedResults/"
}
- Bulk results URLs return CSV; fetch them with a separate GET request.
- state will be "JobComplete" or "Failed".

Required permissions
- API Enabled.
- Object-level create/edit/delete permissions.
- Field-level security (FLS) on every field being written.

Idempotency & limits
- insert is NOT idempotent; retried inserts create duplicates. Use upsert
  with an externalIdField for idempotency.
- Collections: ≤200 records per request; up to 10 chunks of different object
  types per request.
- Bulk API 2.0: 150 million records / 24 h org limit.
- Bulk data upload: ≤150 MB per job (after base64).
- allOrNone=false returns partial success results.

Errors
- INVALID_FIELD / FIELD_CUSTOM_VALIDATION_EXCEPTION.
- DUPLICATE_VALUE on unique fields.
- ENTITY_IS_DELETED on update of recycled record.
- INSUFFICIENT_ACCESS_OR_READONLY (FLS or CRUD violation).
- UNABLE_TO_LOCK_ROW (transient; safe to retry once).

Example request (single insert)

dml_records({
  "operation": "insert",
  "sObject": "Account",
  "records": [{ "Name": "ACME", "Industry": "Technology" }]
})

Response: { "results": [{ "id": "0014Q00000abcDE", "success": true, "errors": [] }] }

Example request (collection update)

dml_records({
  "operation": "update",
  "sObject": "Contact",
  "allOrNone": false,
  "records": [
    { "Id": "003xx000001aaa", "Title": "Engineer" },
    { "Id": "003xx000001bbb", "Title": "Manager" }
  ]
})

Response: { "chunks": [[{ "id": "003xx...", "success": true, "errors": [] }, ...]] }

Example request (upsert by external id)

dml_records({
  "operation": "upsert",
  "sObject": "Account",
  "externalIdField": "External_Account_Id__c",
  "records": [{ "External_Account_Id__c": "EXT-001", "Name": "ACME" }]
})

Response: { "results": [{ "id": "0014Q00000abcDE", "success": true, "errors": [] }] }

Example request (bulk update)

dml_records({
  "operation": "update",
  "sObject": "Contact",
  "useBulk": true,
  "records": [ ... many records with Id ... ]
})
