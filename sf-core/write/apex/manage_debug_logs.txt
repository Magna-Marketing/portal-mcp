Tool: manage_debug_logs

Description
Manage Apex debug log capture using the Tooling API v66.0. Salesforce only
captures debug logs for users that have an active TraceFlag. This tool manages
the full TraceFlag / DebugLevel / ApexLog lifecycle.

Operations:
- enable: resolve user → create DebugLevel → create USER_DEBUG TraceFlag.
- disable: delete active TraceFlag(s) for the user.
- list: SOQL on ApexLog for the user within the last N minutes.
- get: fetch ApexLog metadata + Body text.
- delete: delete a specific ApexLog record.

Salesforce API
Tooling API, v66.0.

Endpoints
POST   /services/data/v66.0/tooling/sobjects/DebugLevel                (enable: create level)
POST   /services/data/v66.0/tooling/sobjects/TraceFlag                 (enable: create flag)
DELETE /services/data/v66.0/tooling/sobjects/TraceFlag/{id}            (disable)
GET    /services/data/v66.0/tooling/query/?q=SELECT ... FROM TraceFlag (disable: find flag)
GET    /services/data/v66.0/tooling/query/?q=SELECT ... FROM ApexLog   (list)
GET    /services/data/v66.0/tooling/sobjects/ApexLog/{id}/Body         (get: log text)
DELETE /services/data/v66.0/tooling/sobjects/ApexLog/{id}              (delete)

TraceFlag key fields:
  TracedEntityId (User Id), DebugLevelId, LogType, StartDate, ExpirationDate.
  ExpirationDate must be ≤ StartDate + 24 h.
  LogType: USER_DEBUG | DEVELOPER_LOG | CLASS_TRACING | PROFILING.

DebugLevel key fields:
  DeveloperName, MasterLabel, Language, ApexCode, ApexProfiling, Callout,
  Database, System, Validation, Visualforce, Workflow.
  Each level: NONE | ERROR | WARN | INFO | DEBUG | FINE | FINER | FINEST.

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Input (parameters)
operation (string, required) - "enable" | "disable" | "list" | "get" | "delete".
userId (string, optional) - Target User ID. Defaults to the OAuth running user.
username (string, optional) - User.Username to look up instead of ID.
durationMinutes (number, optional, default 60, max 1440) - TraceFlag window for enable.
logType (string, optional, default "USER_DEBUG") - TraceFlag LogType for enable/disable.
debugLevels (object, optional) - Per-category levels for enable. Defaults:
  ApexCode=DEBUG, System=DEBUG, Callout/Database/Validation=INFO, rest=NONE.
logId (string, required for get / delete) - ApexLog ID.
limit (number, optional, default 50, max 200) - Max logs for list.
sinceMinutes (number, optional, default 60) - Only logs from the last N minutes for list.

Result (enable)
{
  "traceFlag": { "id", "tracedEntityId", "debugLevelId", "logType", "startDate", "expirationDate", "isActive": true },
  "debugLevel": { "id", "name", "levels": { ... } }
}

Result (disable)
{ "disabled": true, "deletedTraceFlagIds": ["07tXx..."], "tracedEntityId": "005..." }

Result (list)
{ "logs": [{ "Id", "Application", "Operation", "Status", "StartTime", "DurationMilliseconds", "LogLength", "LogUserId" }], "totalSize": N }

Result (get)
{ "log": { ...metadata fields..., "body": "<full log text>" } }

Result (delete)
{ "deleted": true, "id": "07L..." }

Required permissions
- "Author Apex" or "Modify All Data" for trace flags on other users.
- "View All Data" or "Author Apex" to read log bodies.

Idempotency & limits
- disable is idempotent (no-op if no flag found).
- TraceFlag max window 24 h.
- Only one active TraceFlag per user per logType at a time.
- ApexLog rows kept ~24 h before automatic purge.

Errors
- TRACE_FLAG_LIMIT_EXCEEDED: overlapping trace flag exists for user.
- ENTITY_IS_DELETED on get/delete after purge.

Example request (enable for 30 min)

manage_debug_logs({
  "operation": "enable",
  "durationMinutes": 30,
  "debugLevels": { "ApexCode": "DEBUG", "System": "DEBUG" }
})

Example request (list recent logs)

manage_debug_logs({ "operation": "list", "limit": 10, "sinceMinutes": 30 })
