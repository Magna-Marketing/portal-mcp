Tool: write_apex

Description
Create, update, or upsert an Apex class using the Tooling API v66.0
container/member/save pattern.

The old approach of directly calling tooling.sobject('ApexClass').create()
bypasses compilation and is NOT recommended. Use the container pattern:
1. Create a MetadataContainer (workspace scratch-pad).
2. Create an ApexClassMember with the new Body (and ContentEntityId for update).
3. Create a ContainerAsyncRequest to compile + save.
4. Poll until State is terminal: Completed / Failed / Aborted / Invalidated.

Salesforce API
Tooling API, v66.0.

Endpoints
POST /services/data/v66.0/tooling/sobjects/MetadataContainer
POST /services/data/v66.0/tooling/sobjects/ApexClassMember
POST /services/data/v66.0/tooling/sobjects/ContainerAsyncRequest
GET  /services/data/v66.0/tooling/sobjects/ContainerAsyncRequest/{id}   (poll)
DELETE /services/data/v66.0/tooling/sobjects/MetadataContainer/{id}     (cleanup on failure)
GET  /services/data/v66.0/tooling/query/?q=...                          (lookup existing class)

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body (per call)
MetadataContainer:           { "Name": "mcpDeploy_<timestamp>" }
ApexClassMember (create):    { "MetadataContainerId": "<id>", "FullName": "MyClass", "Body": "public class MyClass { ... }" }
ApexClassMember (update):    { "MetadataContainerId": "<id>", "ContentEntityId": "<classId>", "Body": "..." }
ContainerAsyncRequest:       { "MetadataContainerId": "<id>", "IsCheckOnly": false }

ContainerAsyncRequest.State terminal values: Completed | Failed | Aborted | Invalidated

Input (parameters)
operation (string, required) - "create" | "update" | "upsert".
  - create: fails if class already exists.
  - update: fails if class does not exist (looks up by name).
  - upsert: creates if not found, updates if found. Idempotent on name.
name (string, required) - Apex class API name. Must match the class declaration in body.
body (string, required) - Full Apex source. Must compile.
apiVersion (number, optional) - Class ApiVersion (e.g. 62.0). Defaults to org default.
status (string, optional, default "Active") - "Active" | "Inactive".
checkOnly (boolean, optional, default false) - Compile without saving.
  Useful for syntax validation; does NOT create/update the class.

Result
{
  "deploy": {
    "containerId": "<id>",
    "state": "Completed | Failed | Aborted | Invalidated",
    "done": true,
    "errorMessage": null,
    "componentSuccesses": [],
    "componentFailures": [{ "problemType", "problem", "lineNumber", "columnNumber", "fileName" }]
  },
  "apexClass": { "Id", "Name", "ApiVersion", "Status", "IsValid", "LengthWithoutComments", "LastModifiedDate" }
}
apexClass is null on checkOnly or failure.

Required permissions
- "Author Apex".
- Production deploys must achieve ≥75% org-wide coverage on changed classes.

Idempotency & limits
- upsert: idempotent on name.
- create: fails (DUPLICATE_VALUE) if class exists.
- Class body up to ~1 MB.
- Compile errors in componentFailures with line/column.

Errors
- DEPLOY_FAILED with componentFailures.
- INSUFFICIENT_ACCESS_OR_READONLY.
- DEPENDENT_CLASS_INVALID: a dependency is broken.

Example request

write_apex({
  "operation": "upsert",
  "name": "ProjectService",
  "apiVersion": 62.0,
  "body": "public with sharing class ProjectService {\n    public static void doWork() {}\n}\n"
})
