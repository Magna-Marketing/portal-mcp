Tool: execute_anonymous

Description
Execute an Apex code block anonymously as the running OAuth user via the
Tooling API v66.0. Useful for ad-hoc scripts, one-off data fixes, or smoke
tests. The code runs in a single synchronous transaction with normal governor
limits (10 s CPU, 6 MB heap, 100 SOQL, 150 DML).

This does NOT persist any class. Use write_apex to save reusable code.

When captureDebugLog=true the tool:
1. Looks up the running user's ID via /chatter/users/me.
2. Creates a temporary DebugLevel with the requested levels.
3. Creates a temporary USER_DEBUG TraceFlag (5-minute window).
4. Executes the anonymous block.
5. Fetches the generated ApexLog body (GET /tooling/sobjects/ApexLog/{id}/Body).
6. Deletes the temporary TraceFlag and DebugLevel.

Salesforce API
Tooling API, v66.0.

Endpoint
GET /services/data/v66.0/tooling/executeAnonymous/?anonymousBody={url-encoded-source}

(jsforce wraps this as conn.tooling.executeAnonymous(apexCode))

Headers
Authorization: Bearer <access_token>
Accept: application/json

Body
None — source is a query parameter.

Input (parameters)
body (string, required) - Apex code to run. Must end ';' after every statement.
captureDebugLog (boolean, optional, default false) - When true, creates a
  temporary TraceFlag + DebugLevel so the execution generates and retains a
  debug log. The log body and ID are returned. Adds ~1-2s overhead.
debugLevels (object, optional) - Override per-category log levels when
  captureDebugLog=true:
  { ApexCode, ApexProfiling, Callout, Database, System, Validation, Visualforce, Workflow }
  Each accepts: NONE | ERROR | WARN | INFO | DEBUG | FINE | FINER | FINEST.
  Defaults: ApexCode=DEBUG, System=DEBUG, Callout/Database/Validation=INFO, rest=NONE.

Result
{
  "result": {
    "compiled": true,
    "compileProblem": null,
    "line": null,
    "column": null,
    "success": true,
    "exceptionMessage": null,
    "exceptionStackTrace": null
  },
  "debugLog": "<full log text or null>",
  "debugLogId": "07L..."
}

Required permissions
- "Author Apex".
- "View All Data" / "Modify All Data" if code touches restricted data.

Idempotency & limits
- NOT idempotent: DML side effects apply once per call.
- Single-transaction governor limits.
- Source length up to ~100 KB.

Errors
- compiled=false with compileProblem (syntax error before execution).
- success=false with exceptionMessage (runtime exception).
- INSUFFICIENT_ACCESS_OR_READONLY.

Example request

execute_anonymous({
  "body": "Account a = new Account(Name='ACME-Test'); insert a; System.debug('inserted: ' + a.Id);",
  "captureDebugLog": true,
  "debugLevels": { "ApexCode": "DEBUG", "Database": "INFO" }
})

Example result

{
  "result": { "compiled": true, "success": true, "exceptionMessage": null },
  "debugLog": "10:14:23.0 ... USER_DEBUG|[1]|DEBUG|inserted: 0014Q00000abcDE\n",
  "debugLogId": "07L4Q00000XyZab"
}
