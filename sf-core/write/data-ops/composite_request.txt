Tool: composite_request

Description
Bundle multiple REST API sub-requests into a single round trip. Supports
two distinct modes with different capabilities, endpoints, and request shapes.

Mode 1 — composite (default):
  POST /services/data/v66.0/composite
  - Up to 25 sub-requests. Up to 5 may be sObject Collections or Query/QueryAll operations.
  - Each sub-request can reference a prior sub-request's response via @{referenceId.fieldPath}.
  - Controlled rollback via allOrNone (default: false).
  - Optional collation via collateSubrequests to bulk similar DML operations (default: true since API v49.0).
  - Request uses 'compositeRequest' array; each item has method, url, referenceId, body?, httpHeaders?.
  - Response: { "compositeResponse": [{ "referenceId", "httpStatusCode", "body", "httpHeaders" }] }

Mode 2 — batch:
  POST /services/data/v66.0/composite/batch
  - Up to 25 independent sub-requests. No cross-request references allowed.
  - Controlled halt on error via haltOnError (default: false).
  - Request uses 'batchRequests' array; each item has method, url, richInput? (NOT body, NOT referenceId).
  - Response: { "hasErrors": boolean, "results": [{ "statusCode", "result" }] }

KEY DIFFERENCES from original documentation:
- Batch mode uses 'batchRequests' (not 'subrequests') in the request body.
- Batch mode uses 'richInput' (not 'body') for the request payload of each sub-request.
- Batch sub-requests do NOT support referenceId or cross-request references.
- Batch mode uses 'haltOnError' (not 'allOrNone') to control failure behavior.
- The 'collateSubrequests' parameter is composite-mode only and defaults to TRUE since API v49.0.
  When true, unrelated sub-requests of the same method/type may be reordered for bulkification.
  Set to false if execution order matters for unrelated sub-requests.

Salesforce API
Composite REST API, v66.0.

Endpoints
POST /services/data/v66.0/composite           (composite mode — supports cross-reference)
POST /services/data/v66.0/composite/batch     (batch mode — independent sub-requests)

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body (composite mode)
{
  "allOrNone": true,
  "collateSubrequests": false,
  "compositeRequest": [
    { "method": "POST", "url": "/services/data/v66.0/sobjects/Account", "referenceId": "newAccount", "body": { "Name": "ACME" } },
    { "method": "POST", "url": "/services/data/v66.0/sobjects/Contact", "referenceId": "newContact", "body": { "LastName": "Doe", "AccountId": "@{newAccount.id}" } }
  ]
}

Body (batch mode)
{
  "haltOnError": false,
  "batchRequests": [
    { "method": "PATCH", "url": "/services/data/v66.0/sobjects/Account/001xx", "richInput": { "Name": "Updated" } },
    { "method": "GET", "url": "/services/data/v66.0/sobjects/Contact/003xx" }
  ]
}

Input (parameters)
mode ("composite" | "batch", optional, default composite) - Composite execution mode;
enum composite or batch; defaults to composite; example: 'composite'; do not pass graph
here because Composite Graph has a separate tool.
allOrNone (boolean, optional) - Composite allOrNone flag; boolean used only in composite
mode to roll back all subrequests on failure when true; omitted uses Salesforce default
false; example: true; do not pass for batch mode.
collateSubrequests (boolean, optional) - Composite collateSubrequests flag; boolean used
only in composite mode to allow Salesforce to collate unrelated subrequests; omitted
uses Salesforce default; example: false; do not rely on unrelated execution order when
true.
subrequests (unknown[], optional) - Composite subrequests; array required in composite
mode with method, url, referenceId, and optional body/httpHeaders; no default; example:
[{ method: 'GET', referenceId: 'acct', url:
'/services/data/v66.0/sobjects/Account/001...' }]; do not exceed 25 subrequests or 5
query/collection subrequests.
haltOnError (boolean, optional) - Batch haltOnError flag; boolean used only in batch
mode to stop after a subrequest error; omitted uses Salesforce default false; example:
true; do not pass expecting rollback of completed batch subrequests.
batchSubrequests (unknown[], optional) - Batch subrequests; array required in batch mode
with method, url, and optional richInput; no default; example: [{ method: 'GET', url:
'/services/data/v66.0/sobjects/Account/001...' }]; do not include referenceId or
cross-request references.

Result (composite mode)
{ "compositeResponse": [{ "referenceId": "...", "httpStatusCode": 201, "body": {...}, "httpHeaders": {...} }] }

Result (batch mode)
{ "hasErrors": false, "results": [{ "statusCode": 200, "result": {...} }] }

Required permissions
- "API Enabled".

Idempotency & limits
- Up to 25 sub-requests per call.
- Composite mode: up to 5 sub-requests may be sObject Collections or query operations.
- Entire request counts as a single API call toward limits.

Example request

composite_request({
  "mode": "composite",
  "allOrNone": true,
  "collateSubrequests": false
})
