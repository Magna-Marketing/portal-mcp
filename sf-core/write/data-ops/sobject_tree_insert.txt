Tool: sobject_tree_insert

Description
Create a tree of parent and child records in a single API call. An sObject
tree is a nested, parent-child record hierarchy with a single root sObject
type. Child records are nested under their parent using the child relationship
API name (e.g., Contacts, Opportunities). All records in the same request are
created together; if any record fails, the entire request is rolled back.

KEY DIFFERENCES/CORRECTIONS from original documentation:
- The resource supports up to 5 different sObject types per request (not unlimited).
- Trees can be up to 5 levels deep (not unlimited nesting).
- The root sObject type in the URL must match all root-level records' attributes.type.
- referenceId must start with a letter or digit (alphanumeric + underscores only).
- The response structure uses 'hasErrors' and 'results' (not 'results[].success').
  Results include { referenceId, id, errors } for each record. The 'id' field is
  absent when errors occur.
- Triggers, processes, and workflow rules fire per level (all root records together,
  then all second-level records of the same type, etc.) — not per individual record.
- Because the tree can contain a single record, you can use this to bulk-insert up to
  200 unrelated records of the same type in one call.

Salesforce API
REST API (Data), v66.0.

Endpoint
POST /services/data/v66.0/composite/tree/{sObject}

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body
{
  "records": [{
    "attributes": { "type": "Account", "referenceId": "acc1" },
    "Name": "ACME",
    "Contacts": {
      "records": [
        { "attributes": { "type": "Contact", "referenceId": "con1" }, "LastName": "Doe", "Email": "doe@acme.com" }
      ]
    }
  }]
}

Input (parameters)
sObject (string, required) - Root sObject API name; string that must match every root
record's attributes.type; no default; example: 'Account'; do not pass a child
relationship name.
records (unknown[], required) - Root sObject tree records; non-empty array of records
with attributes and writable field values, with children under relationship names; no
default; example: [{ attributes: { type: 'Account', referenceId: 'acc1' }, Name: 'ACME'
}]; do not exceed 200 total records, 5 object types, or 5 levels.

Result
{
  "hasErrors": false,
  "results": [
    { "referenceId": "acc1", "id": "001xx...", "errors": [] },
    { "referenceId": "con1", "id": "003xx...", "errors": [] }
  ]
}

On error (entire request rolled back):
{
  "hasErrors": true,
  "results": [
    { "referenceId": "con1", "errors": [{ "statusCode": "REQUIRED_FIELD_MISSING", "message": "Required fields are missing: [LastName]", "fields": ["LastName"] }] }
  ]
}

Required permissions
- "API Enabled" + Create permission on all sObject types in the tree.

Idempotency & limits
- Not idempotent (creates new records on each call).
- Up to 200 total records across all trees per call.
- Up to 5 different sObject types per request.
- Up to 5 levels of nesting depth.
- All root records must be of the same type (matching the URL sObject parameter).
- Entire request rolls back if any single record fails.
- Counts as a single API call toward limits.

Errors
- INVALID_FIELD on bad child relationship name.
- REQUIRED_FIELD_MISSING if required fields are omitted.
- The error includes the referenceId of the failed record.

Example request

sobject_tree_insert({
  "sObject": "Account",
  "records": "[{ attributes: { type: 'Account', referenceId: 'acc1' }, Name: 'ACME' }]"
})
