Tool: manage_bulk_ingest_job

Description
Full Bulk API 2.0 ingest job lifecycle: create, upload data (CSV),
close (trigger processing), abort, poll status, fetch results, delete, list all jobs.
Use for large-scale DML operations (>~10,000 records) or any time you need
resumable, asynchronous batch processing.

KEY DIFFERENCES/CORRECTIONS from original documentation:
- contentType is ONLY "CSV" — JSON is NOT supported for ingest jobs.
  The original documentation incorrectly suggested JSON as an option.
- uploadData uses PUT (not POST) to /jobs/ingest/{jobId}/batches with Content-Type: text/csv.
- close operation sends PATCH with body { "state": "UploadComplete" } (not "close").
- abort operation sends PATCH with body { "state": "Aborted" } (not "abort").
- The 'listAll' operation (GET /jobs/ingest) supports a 'queryLocator' parameter for pagination,
  not a generic 'nextPage' — the response includes 'nextRecordsUrl' with the locator value.
- 'parseResultsAs' is a client-side convenience option that parses the CSV response into
  an array of row objects when set to "rows".
- Job states from the API: Open → UploadComplete → InProgress → JobComplete | Failed | Aborted.
  Note: 'InProgress' is an actual state returned by the status endpoint (not in original docs).

Salesforce API
Bulk API 2.0, v66.0.

Endpoints
POST   /services/data/v66.0/jobs/ingest                                 (create)
PUT    /services/data/v66.0/jobs/ingest/{jobId}/batches                 (uploadData — Content-Type: text/csv)
PATCH  /services/data/v66.0/jobs/ingest/{jobId}                        (close: { state: "UploadComplete" })
PATCH  /services/data/v66.0/jobs/ingest/{jobId}                        (abort: { state: "Aborted" })
GET    /services/data/v66.0/jobs/ingest/{jobId}                        (status)
GET    /services/data/v66.0/jobs/ingest/{jobId}/successfulResults      (CSV)
GET    /services/data/v66.0/jobs/ingest/{jobId}/failedResults          (CSV)
GET    /services/data/v66.0/jobs/ingest/{jobId}/unprocessedrecords     (CSV — note lowercase 'r')
DELETE /services/data/v66.0/jobs/ingest/{jobId}                        (delete)
GET    /services/data/v66.0/jobs/ingest                                (listAll)

Headers
Authorization: Bearer <access_token>
Content-Type: application/json (create/close/abort)
Content-Type: text/csv (uploadData)

Body (create)
{
  "object": "Account",
  "operation": "insert",
  "contentType": "CSV",
  "lineEnding": "LF",
  "columnDelimiter": "COMMA",
  "externalIdFieldName": null,
  "assignmentRuleId": null
}

Input (parameters)
operation ("create" | "uploadData" | "close" | "abort" | "status" | "successfulResults" | "failedResults" | "unprocessedRecords" | "delete" | "listAll", required) -
Requested Bulk API 2.0 ingest operation; enum create, uploadData, close, abort, status,
successfulResults, failedResults, unprocessedRecords, delete, or listAll; no default;
example: 'create'; do not pass query job operations here.
jobId (string, optional) -
Bulk ingest job Id; Salesforce 750-prefixed job Id string; required for all operations
except create and listAll; example: '750xx000000001aAAA'; do not pass a batch Id or
query job Id.
sObject (string, optional) -
Target sObject API name for create; string standard or custom object name; required for
create; example: 'Account'; do not pass an object label or SOQL query.
ingestOperation ("insert" | "update" | "upsert" | "delete" | "hardDelete", optional) -
Bulk ingest DML operation for create; enum insert, update, upsert, delete, or
hardDelete; required for create; example: 'upsert'; do not use hardDelete without Bulk
API Hard Delete permission.
externalIdFieldName (string, optional) -
External ID field API name for upsert jobs; string required when ingestOperation is
upsert and must appear as a CSV column; example: 'External_Id__c'; do not pass a
relationship field path.
columnDelimiter ("BACKQUOTE" | "CARET" | "COMMA" | "PIPE" | "SEMICOLON" | "TAB", optional) -
CSV column delimiter for create; enum BACKQUOTE, CARET, COMMA, PIPE, SEMICOLON, or TAB;
Salesforce defaults to COMMA when omitted; example: 'COMMA'; do not pass the literal
delimiter character.
lineEnding ("LF" | "CRLF", optional) -
CSV line ending for create; enum LF or CRLF and must match uploaded data; Salesforce
defaults to LF when omitted; example: 'LF'; do not pass platform names such as Windows
or Unix.
assignmentRuleId (string, optional) -
Assignment rule Id for create; Salesforce assignment rule Id applied to Case or Lead
loads; omitted uses default assignment behavior; example: '01Qxx0000004ABC'; do not pass
for unsupported objects.
data (string, optional) -
Raw CSV data for uploadData; string whose first row contains field API names and whose
line endings match the job; required for uploadData; example:
'Name,Industry\\nACME,Tech'; do not pass JSON, base64, or a file path.
queryLocator (string, optional) -
Bulk ingest list pagination locator; string from a previous listAll response when
Salesforce provides one; omitted starts the first page; example: '01gxx000000abc'; do
not pass a full nextRecordsUrl.

Result (per operation)
create:   Full job info including { id, state: "Open", contentUrl, object, operation, contentType, lineEnding, columnDelimiter, createdById, createdDate, systemModstamp, apiVersion, jobType, concurrencyMode, ... }
uploadData: { jobId, status: "uploaded", result: null }
close:    Full job info with state updated to "UploadComplete".
abort:    Full job info with state updated to "Aborted".
status:   { id, state, numberRecordsProcessed, numberRecordsFailed, retries, totalProcessingTime, errorMessage, apiActiveProcessingTime, apexProcessingTime, ... }
successfulResults: { jobId, csv: "..." } or { jobId, rows: [...] } — columns include sf__Id, sf__Created.
failedResults:     { jobId, csv: "..." } or { jobId, rows: [...] } — columns include sf__Id, sf__Error.
unprocessedRecords: { jobId, csv: "..." } or { jobId, rows: [...] }.
delete:   { jobId, deleted: true }
listAll:  { records: [...], done: boolean, nextRecordsUrl?: string }

Required permissions
- "API Enabled" + DML permissions on the sObject.
- "Bulk API Hard Delete" for hardDelete operation.

Idempotency & limits
- Job creation is not idempotent.
- Must call close (UploadComplete) after all uploads — processing does not start without it.
- Results files available for 7 days after job completion.
- Job must be in UploadComplete, JobComplete, Aborted, or Failed state to be deleted.

Errors
- INVALID_JOB_STATE if attempting operations in wrong state.
- DAILY_LIMIT_EXCEEDED for org-level Bulk API limits.

Example request

manage_bulk_ingest_job({
  "operation": "create"
})
