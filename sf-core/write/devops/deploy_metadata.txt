Tool: deploy_metadata

Description
Deploy a metadata package zip + manifest to the org. Supports
`checkOnly` (validate-only), `runTests`, `testLevel`, `rollbackOnError`,
and `ignoreWarnings`. Returns a `deployId` to poll with
`get_deployment_status`.

Salesforce API
Metadata REST API, v66.0.

Endpoint
POST /services/data/v66.0/metadata/deployRequest/{validatedDeployRequestId}
POST /services/data/v66.0/metadata/deployRequest

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body
{
  "deployOptions": {
    "allowMissingFiles": false,
    "autoUpdatePackage": false,
    "checkOnly": false,
    "ignoreWarnings": false,
    "performRetrieve": false,
    "purgeOnDelete": false,
    "rollbackOnError": true,
    "runTests": ["ProjectServiceTest"],
    "singlePackage": true,
    "testLevel": "RunSpecifiedTests"
  },
  "deployBase64": "UEsDB..."
}

Input (parameters)
zipBase64 (string, optional) - Base64 package zip containing package.xml and metadata
files; string; required unless validatedDeployRequestId is passed; example \"UEsDB...\";
do not pass raw binary, a filesystem path, or an unpacked folder.
validatedDeployRequestId (string, optional) - Validated deploy request Id for quick
deploy; Salesforce Id string; when set the zip and deploy options are ignored; example
\"0Af...\"; only pass a recent successful validation that Salesforce still allows quick
deploying.
checkOnly (boolean, optional) - Whether to validate without committing metadata;
boolean; defaults to false; example true; do not use with validatedDeployRequestId.
rollbackOnError (boolean, optional) - Whether any component failure rolls back the whole
deploy; boolean; defaults to true in this tool and is required for production; example
true; do not set false for production deploys.
ignoreWarnings (boolean, optional) - Whether Metadata API warnings can still allow
success; boolean; defaults to false; example true; do not use to ignore actual component
errors.
allowMissingFiles (boolean, optional) - Whether package.xml members missing from the zip
are tolerated; boolean; defaults to false; example false; do not enable for strict
release packages.
autoUpdatePackage (boolean, optional) - Whether Salesforce can update package.xml from
extra zip files; boolean; defaults to false; example false; avoid unless performing
retrieve-after-deploy packaging flows.
performRetrieve (boolean, optional) - Whether Salesforce performs a retrieve after
deploy; boolean; defaults to false; example false; do not expect this to replace
retrieve_metadata.
purgeOnDelete (boolean, optional) - Whether destructive changes bypass the Recycle Bin
where supported; boolean; defaults to false; example true; do not pass true unless
permanent deletion is intended.
runTests (string[], optional) - Apex test class names to run; array of class names;
required when testLevel is RunSpecifiedTests; example [\"AccountTriggerTest\"]; do not
pass method names or Ids.
testLevel (string, optional) - Deployment test level; enum string; Salesforce chooses
defaults when omitted; example \"RunLocalTests\"; RunSpecifiedTests requires runTests.
singlePackage (boolean, optional) - Whether the zip contains a single package structure;
boolean; defaults to true; example true; set false only for multi-package zips.
filename (string, optional) - Multipart file name for the zip part; string ending in
.zip is recommended; defaults to deploy.zip; example \"release.zip\"; do not include
directory paths.

Result
the raw deployRequest response, returned as soon as Salesforce accepts the request. This
tool does not wait for the deploy to finish. Call read.get_deployment_status with the
returned id on a later step, and call it again while deployResult.status is not
Succeeded, SucceededPartial, Failed, or Canceled and deployResult.done is not true.

Required permissions
- "Modify Metadata Through Metadata API Functions" + (production) "Deploy Change Sets".

Idempotency & limits
- A deploy is not idempotent — same zip applied twice may trigger Apex compile and tests both times.
- Production deploys mandate ≥75% code coverage and a real test run.

Errors
- DEPLOY_FAILED with componentFailures, INSUFFICIENT_TEST_COVERAGE.

Example request

deploy_metadata({
  "zipBase64": "example",
  "validatedDeployRequestId": "example",
  "checkOnly": false
})
