Tool: update_lwc_file

Description
Update a single file in an existing LWC bundle. PATCHes the Source of the
matching LightningComponentResource. If the file does not exist, the call
fails — use `add_lwc_file` instead.

Salesforce API
Tooling API, v66.0. Direct CRUD.

Endpoints
GET   /services/data/v66.0/tooling/query/?q=SELECT Id, FilePath, Format, Source FROM LightningComponentResource WHERE LightningComponentBundleId = '{bundleId}'
PATCH /services/data/v66.0/tooling/sobjects/LightningComponentResource/{id}

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body (PATCH)
{ "Source": "..." }

Note: Salesforce returns HTTP 204 No Content for a successful PATCH. The tool
returns { resourceId, filePath, format, updateResult: { success: true } }.

Input (parameters)
bundleName (string, required) - DeveloperName of the bundle.
fileName (string, required) - File name including extension, e.g.
  projectCard.js or projectCard.js-meta.xml.
source (string, required) - New file contents.
expectedFormat (string, optional) - Format assertion: "js" | "html" | "css"
  | "xml" | "svg" | "json". Returns an error if the inferred format differs.

Result
resourceId (string) - LightningComponentResource Id.
filePath (string) - Full FilePath value.
format (string) - Inferred format.
updateResult (object) - Raw PATCH response (or { success: true } for 204).

Required permissions
- "Customize Application".

Idempotency & limits
- Idempotent on equal source.

Errors
- NOT_FOUND if bundle or file doesn't exist.

Example request

update_lwc_file({
  "bundleName": "projectCard",
  "fileName": "projectCard.js",
  "source": "import { LightningElement, api } from 'lwc';\nexport default class ProjectCard extends LightningElement { @api recordId; }\n"
})
