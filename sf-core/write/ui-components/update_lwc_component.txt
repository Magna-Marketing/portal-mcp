Tool: update_lwc_component

Description
Update one or more files in an existing LWC bundle. Supply any combination
of js, html, css, xml, or svg content. Each supplied file is PATCHed if it
exists or POSTed if new. Unprovided files are left untouched.

Salesforce API
Tooling API, v66.0. Direct CRUD.

Endpoints
GET   /services/data/v66.0/tooling/query/?q=SELECT Id, FilePath, Format, Source FROM LightningComponentResource WHERE LightningComponentBundleId = '{bundleId}'
POST  /services/data/v66.0/tooling/sobjects/LightningComponentResource       (per new file)
PATCH /services/data/v66.0/tooling/sobjects/LightningComponentResource/{id}  (per existing file)

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body (PATCH existing)
{ "Source": "..." }

Body (POST new)
{ "LightningComponentBundleId": "<id>", "FilePath": "...", "Format": "js", "Source": "..." }

Input (parameters)
name (string, required) - DeveloperName of the bundle to update.
js (string, optional).
html (string, optional).
css (string, optional).
xml (string, optional) - Meta XML content.
svg (string, optional).

Result (raw Tooling API responses)
bundleId (string).
files (object) - Map of fileName → { id, success, errors } or { success: true } for 204.

Required permissions
- "Customize Application".

Idempotency & limits
- Idempotent on equal source.

Errors
- NOT_FOUND on name.

Example request

update_lwc_component({
  "name": "projectCard",
  "js": "import { LightningElement, api } from 'lwc';\nexport default class ProjectCard extends LightningElement { @api recordId; }\n",
  "css": ":host { display: block; padding: 1rem; }"
})
