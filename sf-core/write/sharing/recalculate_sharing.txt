Tool: recalculate_sharing

Description
Trigger an asynchronous sharing recalculation for an sObject's sharing
rules. Used after creating/updating rules or in support cases when
sharing seems incorrect. Returns a job Id; poll status with the
`SharingRecalcStatus` view.

Salesforce API
Metadata API (SOAP), v66.0.

Endpoint
POST /services/Soap/m/66.0  (updateMetadata SharingRules)

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body
{ "SObjectType": "Account" }

Input (parameters)
sObject (string, required) - Represents the sObject API name whose SharingRules metadata
is re-saved; standard or custom object name; no default; example 'Account'; do not pass
the .sharingRules file name.
checkOnly (boolean, optional) - Represents whether to read and return metadata without
calling updateMetadata; boolean; defaults to false; example true; do not use when
recalculation must be triggered.
waitForCompletion (boolean, optional) - Represents a compatibility flag for waiting;
boolean; defaults to false and is reported as unsupported; example false; do not rely on
it for polling recalculation.

Result
JSON object with checkOnly, waitForCompletionRequested, waitForCompletionSupported,
readResponse, metadata, and updateResponse.
checkOnly (value) - included in the JSON returned by the tool.
waitForCompletionRequested (value) - included in the JSON returned by the tool.
waitForCompletionSupported (value) - included in the JSON returned by the tool.
readResponse (value) - included in the JSON returned by the tool.
metadata (value) - included in the JSON returned by the tool.
updateResponse (value) - included in the JSON returned by the tool.

Required permissions
- "Manage Sharing" + "Modify All Data".

Idempotency & limits
- Multiple recalcs in the same window are coalesced server-side.

Errors
- SHARING_RECALC_IN_PROGRESS, INSUFFICIENT_ACCESS_OR_READONLY.

Example request

recalculate_sharing({
  "sObject": "example"
})
