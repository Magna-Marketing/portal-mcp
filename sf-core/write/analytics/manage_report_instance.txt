Tool: manage_report_instance

Description
Manage asynchronous report run instances. Use this for reports that exceed
the 2,000-row synchronous cap or take more than 30 s to compute. Operations:
- `start`: kick off a new instance and return its metadata with status "New".
- `status`: poll a running instance for its current status.
- `results`: retrieve a completed instance's factMap and metadata.
- `list`: list recent instances for a report.
- `cancel`: cancel an in-progress instance via DELETE.

Instance status: New -> Running -> Success (or Error / Cancelled).

Salesforce API
Analytics REST API, v66.0. `/analytics/reports/{reportId}/instances`.

All operations require `reportId`. The `instanceId` is additionally required
for `status`, `results`, and `cancel`.

NOTE: The old implementation incorrectly used `/analytics/reportInstances/{id}`
(without the reportId prefix). The correct endpoint for all instance operations
is `/analytics/reports/{reportId}/instances[/{instanceId}]`.

Endpoints
POST   /services/data/v66.0/analytics/reports/{reportId}/instances          (start)
GET    /services/data/v66.0/analytics/reports/{reportId}/instances          (list)
GET    /services/data/v66.0/analytics/reports/{reportId}/instances/{instanceId}   (status / results)
DELETE /services/data/v66.0/analytics/reports/{reportId}/instances/{instanceId}   (cancel)

Headers
Authorization: Bearer <access_token>
Accept: application/json
Content-Type: application/json   (only for POST start)

Body (start with metadata overrides — optional)
{
  "reportMetadata": {
    "reportFilters": [{ "column": "OWNER.NAME", "operator": "equals", "value": "Yamin Haji" }],
    "standardDateFilter": { "column": "CLOSE_DATE", "durationValue": "THIS_FY" }
  }
}

Input (parameters)
operation (string, required) - "start" | "status" | "results" | "list" | "cancel".
reportId (string, required) - Report ID (required for ALL operations).
instanceId (string, required for status / results / cancel) - Instance ID.
overrideMetadata (object, optional, only for start) - Partial reportMetadata
  overrides applied only to this run (e.g. reportFilters, standardDateFilter).
includeDetails (boolean, optional, default true, only for results) - Include
  row-level detail data in the response.
limit (number, optional, default 200, max 2000, only for list).

Result (start)
Raw API response: { id, status ("New"), requestDate, ownerId, hasDetailRows, ... }

Result (status / results)
Raw API response: same instance object; `status` evolves to Running/Success/Error/Cancelled.
When status = Success, results also includes factMap, groupings, reportMetadata.

Result (list)
Raw API response: array of instance summaries { id, status, requestDate, completionDate, ownerId }.

Result (cancel)
Raw API response: null or empty (204 No Content on success).

Required permissions
- "API Enabled".
- Read on the report's folder.
- "Manage Reports" to cancel another user's instance.

Idempotency & limits
- `start` is NOT idempotent (each call creates a new instance).
- Up to 100,000 rows per instance; 5 concurrent instances per report per user.
- Instance metadata is retained ~24 h then purged.

Errors
- INVALID_REPORT_ID, INVALID_INSTANCE_ID
- REPORT_INSTANCE_NOT_READY: results requested before status = Success
- TOO_MANY_INSTANCES

Example request (start with overrides)

manage_report_instance({
  "operation": "start",
  "reportId": "00OQg0000004aBcDE",
  "overrideMetadata": {
    "reportFilters": [{ "column": "AMOUNT", "operator": "greaterOrEqual", "value": "100000" }]
  }
})

Example request (results once complete)

manage_report_instance({
  "operation": "results",
  "reportId": "00OQg0000004aBcDE",
  "instanceId": "0LGQg00000abcDE",
  "includeDetails": true
})
