Tool: create_flow

Description
Create a new Salesforce Flow. Two mutually exclusive modes:
1. **Template**: pass `template` to generate a well-formed Flow XML skeleton. The
   following templates are supported:
   - `record_triggered_before_save` – AutoLaunchedFlow + Before-Save trigger
   - `record_triggered_after_save`  – AutoLaunchedFlow + After-Save trigger
   - `autolaunched`                 – AutoLaunchedFlow, no trigger (invocable)
   - `screen_form`                  – Screen Flow (processType=Flow) with one blank screen
   - `screen_lookup`                – Screen Flow with a Get Records node
   - `scheduled`                    – AutoLaunchedFlow with Scheduled trigger
2. **Custom XML**: pass `xml` for full control over the Flow body.

The flow XML is packaged into a deployment zip and sent to Salesforce using
the Metadata REST API deployRequest endpoint (multipart/form-data). It is
saved as **Draft** by default. To activate, either:
  - Pass `activateAfterDeploy: true` (tool activates via Tooling API after deploy), or
  - Include `<status>Active</status>` in the XML body (modern approach, API v44+).

API Corrections (vs. earlier documentation):
- The endpoint requires multipart/form-data with a zip file, NOT a plain JSON body.
- `processType: "ScreenFlow"` is INVALID. Use `processType: "Flow"` for screen flows.
- Record-triggered flows use `processType: "AutoLaunchedFlow"` with the `start`
  element's `triggerType` (RecordBeforeSave / RecordAfterSave).
- Activation after deploy uses the Tooling API FlowDefinition PATCH, not metadata deploy.

Salesforce API
Metadata REST API v66.0 — deployRequest (multipart/form-data with zip).
Tooling API v66.0 — FlowDefinition PATCH (for activateAfterDeploy only).

Endpoints
POST /services/data/v66.0/metadata/deployRequest       (multipart/form-data)
PATCH /services/data/v66.0/tooling/sobjects/FlowDefinition/{id}  (activate only)

Headers
Authorization: Bearer <access_token>
Content-Type: multipart/form-data; boundary=<boundary>

Multipart body parts
1. json part: { "deployOptions": { "checkOnly": false, "singlePackage": true, ... } }
2. file part: zip archive containing:
   - package.xml  (declares Flow type + version)
   - flows/<FlowApiName>.flow  (the Flow XML)

Input (parameters)
fullName (string, required) - Flow API name/DeveloperName; API name string; required;
example \"Account_Trigger_Flow\"; do not include version suffixes.
label (string, required) - Flow label; string; required in template mode; example
\"Account Trigger Flow\"; xml mode can carry its own label.
description (string, optional) - Flow description; string; optional; example \"Updates
account risk\"; avoid secrets.
template (string, optional) - Built-in starter template; enum string; mutually exclusive
with xml; example \"record_triggered_after_save\"; do not pass unsupported flow
categories.
templateOptions (object, optional) - Template configuration; object; optional; example
{\"objectType\":\"Account\"}; ignored in xml mode.
  objectType (string, optional) - sObject API name; string; required for
  record-triggered, lookup, and scheduled templates; example \"Account\"; do not pass
  labels.
  recordTriggerType ("Create" | "Update" | "CreateAndUpdate" | "Delete", optional) -
  Record trigger operation; enum string; required for record-triggered templates;
  example \"CreateAndUpdate\"; Delete is not valid for before-save update templates.
  startDate (string, optional) - Schedule start date; YYYY-MM-DD string; used by
  scheduled template; example \"2026-06-01\"; do not pass datetime values.
  startTime (string, optional) - Schedule start time; HH:MM:SS.000Z string; used by
  scheduled template; example \"00:00:00.000Z\"; include Z suffix.
  frequency ("Once" | "Daily" | "Weekly", optional) - Schedule frequency; enum Once,
  Daily, or Weekly; defaults to Daily; example \"Daily\"; omit for default.
xml (string, optional) - Complete Flow metadata XML; string; mutually exclusive with
template; example \"<Flow xmlns=...>\"; do not pass partial XML fragments.
runInMode ("DefaultMode" | "SystemModeWithoutSharing", optional) - Flow run mode; enum
string; defaults to DefaultMode; example \"SystemModeWithoutSharing\"; only used by
generated templates.
checkOnly (boolean, optional) - Validation-only flag; boolean; defaults to false;
example true; true does not save the flow.
activateAfterDeploy (boolean, optional) - Activation flag after successful deploy;
boolean; defaults to false; example true; do not enable until the flow is ready to run.
testLevel ("NoTestRun" | "RunLocalTests" | "RunAllTestsInOrg", optional) - Deploy test
level; enum string; defaults to NoTestRun; example \"RunLocalTests\"; production rules
can require tests.

Result
raw deploy status plus FlowDefinition query response and optional activation result.
deployResult (value) - included in the JSON returned by the tool.
flowDefinition (value) - included in the JSON returned by the tool.
activationError (value) - included in the JSON returned by the tool.
activationResult (value) - included in the JSON returned by the tool.

Required permissions
- "Manage Flow" + "Customize Application"

Idempotency & limits
- create_flow will fail if `fullName` already exists; use update_flow.
- Each successful deploy creates a new version. Max 50 versions per Flow.

Errors
- DUPLICATE_DEVELOPER_NAME – flow with fullName already exists.
- INVALID_FLOW_DEFINITION – invalid or missing XML elements.
- Deploy failures appear in deployResult.details.componentFailures.

Example request

create_flow({
  "fullName": "example",
  "label": "example"
})
