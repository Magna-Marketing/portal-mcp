Tool: update_flow

Description
Update an existing Salesforce Flow by deploying a new version. Each successful deploy
creates a new draft version under the same FlowDefinition. The currently active version
is NOT affected unless you also pass `activateAfterDeploy: true` or include
`<status>Active</status>` in the XML.

API Corrections (vs. earlier documentation):
- The endpoint requires multipart/form-data with a zip file, NOT a plain JSON body.
- There is no separate concept of "deactivateOldVersions" — Salesforce enforces that
  only one version is active at a time; activating a new version automatically deactivates
  the old active one.
- The modern approach (API v44+) to activate a new version is to set
  `<status>Active</status>` inside the Flow XML. Alternatively use activateAfterDeploy.

Salesforce API
Metadata REST API v66.0 — deployRequest (multipart/form-data with zip).
Tooling API v66.0 — FlowDefinition PATCH (for activateAfterDeploy only).

Endpoints
POST /services/data/v66.0/metadata/deployRequest       (multipart/form-data)
PATCH /services/data/v66.0/tooling/sobjects/FlowDefinition/{id}  (activate only)

Headers
Authorization: Bearer <access_token>
Content-Type: multipart/form-data; boundary=<boundary>

Multipart body parts
1. json part: { "deployOptions": { "checkOnly": false, "singlePackage": true, ... } }
2. file part: zip archive containing:
   - package.xml  (declares Flow type + version)
   - flows/<FlowApiName>.flow  (the updated Flow XML)

Input (parameters)
fullName (string, required) - Existing Flow API name/DeveloperName; API name string;
required; example \"Account_Trigger_Flow\"; do not include a version suffix.
xml (string, required) - Complete Flow metadata XML for the new version; string;
required; example \"<Flow xmlns=...>\"; do not pass partial XML or JSON.
checkOnly (boolean, optional) - Validation-only flag; boolean; defaults to false;
example true; true does not create a new saved version.
activateAfterDeploy (boolean, optional) - Activation flag after successful deploy;
boolean; defaults to false; example true; do not enable until the version is safe to
run.
testLevel ("NoTestRun" | "RunLocalTests" | "RunAllTestsInOrg", optional) - Deploy test
level; enum string; defaults to NoTestRun; example \"RunLocalTests\"; production rules
can require tests.

Result
raw deploy status plus FlowDefinition query response and optional activation result.
deployResult (value) - included in the JSON returned by the tool.
flowDefinition (value) - included in the JSON returned by the tool.
activationError (value) - included in the JSON returned by the tool.
activationResult (value) - included in the JSON returned by the tool.

Required permissions
- "Manage Flow" + "Customize Application"

Idempotency & limits
- Re-running with the same XML still creates a new version. NOT idempotent.
- Max 50 versions per Flow; use Salesforce Flow Builder to purge old versions.

Errors
- NOT_FOUND / INVALID_CROSS_REFERENCE_KEY – fullName doesn't exist (use create_flow).
- INVALID_FLOW_DEFINITION – invalid or missing XML elements.
- Deploy failures appear in deployResult.details.componentFailures.

Example request

update_flow({
  "fullName": "example",
  "xml": "example"
})
