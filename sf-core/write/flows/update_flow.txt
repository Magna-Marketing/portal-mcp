Tool: update_flow

Description
Update an existing Salesforce Flow by deploying a new version. Each successful deploy
creates a new draft version under the same FlowDefinition. The currently active version
is NOT affected unless you also pass `activateAfterDeploy: true` or include
`<status>Active</status>` in the XML.

API Corrections (vs. earlier documentation):
- The endpoint requires multipart/form-data with a zip file, NOT a plain JSON body.
- There is no separate concept of "deactivateOldVersions" — Salesforce enforces that
  only one version is active at a time; activating a new version automatically deactivates
  the old active one.
- The modern approach (API v44+) to activate a new version is to set
  `<status>Active</status>` inside the Flow XML. Alternatively use activateAfterDeploy.

Salesforce API
Metadata REST API v66.0 — deployRequest (multipart/form-data with zip).
Tooling API v66.0 — FlowDefinition PATCH (for activateAfterDeploy only).

Endpoints
POST /services/data/v66.0/metadata/deployRequest       (multipart/form-data)
PATCH /services/data/v66.0/tooling/sobjects/FlowDefinition/{id}  (activate only)

Headers
Authorization: Bearer <access_token>
Content-Type: multipart/form-data; boundary=<boundary>

Multipart body parts
1. json part: { "deployOptions": { "checkOnly": false, "singlePackage": true, ... } }
2. file part: zip archive containing:
   - package.xml  (declares Flow type + version)
   - flows/<FlowApiName>.flow  (the updated Flow XML)

Input (parameters)
fullName (string, required) – Existing Flow API name (DeveloperName).
xml (string, required) – Full <Flow> XML document for the new version. Must include
  the root <Flow xmlns="http://soap.sforce.com/2006/04/metadata"> element.
  To activate as part of the deploy, include <status>Active</status> in the XML.
apiVersion (number, optional, default 66.0) – Version declared in package.xml.
checkOnly (boolean, optional, default false) – Validate without saving.
activateAfterDeploy (boolean, optional, default false) – After a successful deploy,
  activate the new version using the Tooling API FlowDefinition PATCH.
testLevel (string, optional, default "NoTestRun") – "NoTestRun" | "RunLocalTests" |
  "RunAllTestsInOrg".

Result
deployResult (object) – Raw Salesforce deploy status, including:
  deployResult.id, deployResult.done, deployResult.status,
  deployResult.details.componentSuccesses[], deployResult.details.componentFailures[].
flowDefinition (object|null, on success) – Tooling API FlowDefinition info:
  { definitionId, masterLabel, latestVersionNumber, latestVersionId,
    activeVersionNumber, activeVersionId }.
activationResult (object|null) – Present when activateAfterDeploy=true.

Required permissions
- "Manage Flow" + "Customize Application"

Idempotency & limits
- Re-running with the same XML still creates a new version. NOT idempotent.
- Max 50 versions per Flow; use Salesforce Flow Builder to purge old versions.

Errors
- NOT_FOUND / INVALID_CROSS_REFERENCE_KEY – fullName doesn't exist (use create_flow).
- INVALID_FLOW_DEFINITION – invalid or missing XML elements.
- Deploy failures appear in deployResult.details.componentFailures.

Example request

update_flow({
  "fullName": "Account_Trigger_Flow",
  "xml": "<?xml version=\"1.0\" encoding=\"UTF-8\"?>\n<Flow xmlns=\"http://soap.sforce.com/2006/04/metadata\">\n  <apiVersion>66.0</apiVersion>\n  <label>Account Trigger Flow</label>\n  <processType>AutoLaunchedFlow</processType>\n  <start>\n    <locationX>50</locationX><locationY>0</locationY>\n    <object>Account</object>\n    <recordTriggerType>Create</recordTriggerType>\n    <triggerType>RecordBeforeSave</triggerType>\n  </start>\n  <status>Draft</status>\n</Flow>",
  "activateAfterDeploy": true
})
