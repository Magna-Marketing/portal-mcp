Tool: list_transactional_definitions

Description
List Transactional Messaging definitions (email + SMS). Each
definition is a stable shape (subject, content reference, sender, send
classification) addressed by a `definitionKey`; `send_transactional_email`
/ `send_transactional_sms` invoke a definition to actually send.

Marketing Cloud API
REST API (`/messaging/v1/email/definitions`, `/messaging/v1/sms/definitions`).

Endpoint
GET https://{tenant}.rest.marketingcloudapis.com/messaging/v1/email/definitions
GET https://{tenant}.rest.marketingcloudapis.com/messaging/v1/sms/definitions

Headers
Authorization: Bearer <access_token>
Accept: application/json

Body
None.

Input (parameters)
type ("email" | "sms", required) - Transactional channel to list. Use email for /messaging/v1/email/definitions or sms for
/messaging/v1/sms/definitions.
status ("active" | "inactive" | "deleted", optional) - Optional Salesforce status filter. Valid values are active, inactive, or deleted.
status_operator ("eq" | "neq", optional) - Operator used with status. Salesforce documents eq and neq. Defaults to eq.
page (number, optional) - Salesforce $page value. Defaults to 1.
page_size (number, optional) - Salesforce $pageSize value. Defaults to 50, maximum 50.
order_by ("definitionKey" | "name" | "createdDate" | "modifiedDate" | "status", optional) - Optional Salesforce $orderBy dimension. Accepted values are definitionKey, name,
createdDate, modifiedDate, and status.
raw_filter (string, optional) - Optional raw Salesforce $filter value. When supplied, it overrides status and
status_operator. Use for advanced documented filters such as "status neq deleted".
business_unit_id (string, optional) - Business Unit MID used to scope the access token and Account-Context header for this
Transactional Messaging REST request.

Result
Raw Marketing Cloud response JSON, returned unchanged.

Required scopes
- `email_send` (email) / `sms_send` (sms).

Idempotency & limits
- Read-only.

Errors
- 10000 bad request.

Example request

list_transactional_definitions({
  "type": "email"
})
