Tool: send_transactional_sms

Description
Send a transactional SMS via a defined Transactional Messaging SMS
definition. Modern, idempotent, and supports per-recipient attribute
overrides.

Marketing Cloud API
REST API (`/messaging/v1/sms/messages/{messageKey}`).

Endpoint
POST https://{tenant}.rest.marketingcloudapis.com/messaging/v1/sms/messages/{message_key}
POST https://{tenant}.rest.marketingcloudapis.com/messaging/v1/sms/messages

Headers
Authorization: Bearer <access_token>
Content-Type: application/json

Body
POST: content, definitionKey

Input (parameters)
definition_key (string, required) - Transactional Messaging SMS send definition key. Salesforce sends the message using this
definition.
recipients (object[], required) - Recipients to send to. Use one recipient with message_key for the single-recipient
endpoint, or multiple recipients for the batch endpoint.
message_key (string, optional) - Required for the single-recipient endpoint. When provided, recipients must contain
exactly one recipient and the tool calls POST /messaging/v1/sms/messages/{messageKey}.
message_content (string, optional) - Optional SMS body override. Passed as content.message, which Salesforce documents for
transactional SMS sends.
content (object, optional) - Optional Salesforce content object. Use this for advanced documented overrides. If
message_content is also supplied, it is written to content.message.
request_body_overrides (object, optional) - Optional advanced Salesforce request body fields to merge into the final request body.
Values here override generated fields.
business_unit_id (string, optional) - Business Unit MID used to scope authentication and the Account-Context header for this
Transactional Messaging REST request.

Result
Raw Marketing Cloud response JSON, returned unchanged.

Required scopes
- `sms_send`.

Idempotency & limits
- Idempotent on `messageKey`.
- Subject to MobileConnect SMS rate limits and short-code throughput.

Errors
- DUPLICATE_MESSAGE_KEY, DEFINITION_INACTIVE, INVALID_PHONE_NUMBER.

Example request

send_transactional_sms({
  "definition_key": "",
  "recipients": []
})
