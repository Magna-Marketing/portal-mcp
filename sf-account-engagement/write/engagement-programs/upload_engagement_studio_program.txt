Tool: upload_engagement_studio_program

Description
Create an Engagement Studio program by uploading a YAML structure
file. The YAML defines the step graph (rules / actions / triggers /
email sends / branches). Use `download_program_structure` to
round-trip an existing program, modify it, and re-upload as a new
program (v5 doesn't expose update on existing programs).

Salesforce API
Account Engagement v5 REST API.

Endpoint
POST https://{pi-domain}/api/v5/objects/engagement-studio-programs

Headers
Authorization: Bearer <salesforce-access-token>
Pardot-Business-Unit-Id: <buId>
Content-Type: multipart/form-data
Accept: application/json

Body
POST multipart parts: engagementStudioProgram, file

Input (parameters)
name (string, required) - Program name. Required.
description (string, optional) - Optional description of the program.
recipientListId (number, required) - Id of the prospect list that feeds into this program. Required.
suppressionListIds (number[], optional) - Lists whose members are excluded from the program.
businessHoursId (number, optional) - Business hours schedule id. Defaults to the BU default.
scheduleType ("Continuous" | "Schedule", optional) - "Continuous" enrolls new prospects automatically; "Schedule" uses a defined run window.
campaignId (number, optional) - Campaign to attribute program activity to.
folderId (number, optional) - Folder to organize the program in.
programStructureYaml (string, required) - YAML definition of the step graph (rules, actions, triggers, email sends, branches).
Required.

Result
Raw Account Engagement response JSON, returned unchanged.

Required scopes
- `pardot_api`.

Idempotency & limits
- Not idempotent; each call creates a new program.
- Up to 300 steps per program.

Errors
- 600 invalid_program_structure (YAML schema), 53 not_permitted,
  59 not_found (recipientListId, businessHoursId).

Example request

upload_engagement_studio_program({
  "name": "",
  "recipientListId": 1,
  "programStructureYaml": ""
})

Example result

{ }
